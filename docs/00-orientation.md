## 1. 이 시험의 성격

AICE Professional 실기는 주피터 노트북 환경에서 데이터를 받아 **모델을 만들고 예측 결과를 제출**하는 형식입니다.
시험 시간은 **총 180분**이고, 정형(Tabular) · 텍스트(Text) · 이미지(Image) 중 하나 또는 둘이 출제됩니다.
요구사항은 대체로 이 형태입니다.

> "주어진 `train.csv`로 모델을 학습시키고, `test.csv`에 대한 예측 결과를 `submission.csv`로 저장하시오."

여기서 나오는 함정은 대부분 **모델 성능이 아니라 절차**에서 나옵니다.

- 전처리를 test에도 똑같이 적용했는가
- 스케일러를 test로 `fit` 하지 않았는가
- 제출 파일의 행 수와 컬럼명이 요구사항과 맞는가

즉 정확도 0.93을 0.95로 올리는 일보다, **끝까지 도는 코드를 시간 안에 완성하는 일**이 점수에 직결됩니다.
이 과정의 모든 선택은 그 기준으로 내려져 있습니다.

## 2. 시험 환경 — 코드보다 먼저 알아야 할 것

여기서 실수하면 실력과 무관하게 점수를 잃습니다. **네 가지를 몸에 익혀 두세요.**

### ① 문제와 함께 분석 자료가 주어진다

데이터를 처음부터 뒤져서 파악하는 시험이 아닙니다.
**컬럼 설명, 데이터 정의, 요구사항이 문서로 제공됩니다.**

그래서 시작하자마자 코드를 치는 것은 손해입니다. 먼저 분석 자료를 읽고 이걸 확정하세요.

- 타겟 컬럼이 무엇인가
- 각 컬럼이 무슨 의미인가 (→ 어느 컬럼이 누수인지 여기서 드러납니다)
- 제출 파일 형식과 요구 지표가 무엇인가

`docs/01-tabular.md`에서 배울 "컬럼 요약표"는 **분석 자료를 대체하는 게 아니라 교차 검증하는 도구**입니다.
자료에서 "이 컬럼은 결과값을 사후에 기록한 것"이라 적혀 있으면, 상관계수를 볼 필요도 없이 제거 대상입니다.

### ② GPU는 자동으로 붙지 않는다 — 시작할 때 한 번

시험 환경은 **Colab 무료 T4와 비슷한 성능**의 GPU를 제공하지만,
**시작할 때 GPU 연결 코드를 직접 실행해야 합니다.**

이걸 빼먹으면 CPU로 학습이 돌아갑니다. 이미지 전이학습이나 BERT는 CPU에서 수십 배 느려지고,
"왜 이렇게 오래 걸리지" 하다가 시험이 끝납니다. **가장 먼저 실행할 셀입니다.**

```python
# 시험 시작 후 첫 번째 셀 — 세션당 딱 한 번
!nvidia-smi

import tensorflow as tf
gpus = tf.config.list_physical_devices('GPU')
print(f"GPU: {gpus}")
assert gpus, "GPU 미연결! 런타임 설정을 확인하세요"
```

`assert`를 넣어 두는 이유는, GPU가 없으면 **조용히 CPU로 돌아가기 때문**입니다.
에러로 멈춰야 알아차립니다.

**한 번이면 끝입니다.** 한 세션 안에서는 연결이 유지되므로, 문제가 몇 개든 다시 확인하지 않습니다.
그래서 이 과정의 템플릿은 GPU 확인을 [templates/00_session_start.py](../templates/00_session_start.py) 한 곳에만 두고,
도메인별 템플릿에서는 하지 않습니다.

### ③ 저장하지 않으면 날아간다

작성한 코드가 자동 저장되지 않습니다. **미저장 상태에서 세션이 끊기면 전부 사라집니다.**

- 셀 하나를 완성할 때마다 `Ctrl+S`
- 최소한 **단계가 끝날 때마다** (전처리 완료 → 저장, 모델 비교 완료 → 저장)
- 긴 학습을 시작하기 **직전에** 반드시 저장

이건 습관의 문제라 시험장에서 새로 만들어지지 않습니다. **연습할 때부터 저장하세요.**

### ④ 제출 파일명은 휴대폰 번호 + 문제 번호

모델과 예측 결과를 **본인 휴대폰 번호와 문제 번호**로 저장해 제출합니다.

```
01012345678_1.pkl     # 1번 문제의 모델
01012345678_1.csv     # 1번 문제의 예측 결과
```

번호는 하이픈 없이 붙여 씁니다. 이름이 틀리면 채점이 안 될 수 있으므로,
템플릿처럼 **변수로 한 번만 적고 f-string으로 만드는 방식**을 쓰세요.

```python
PHONE = '01012345678'    # 세션 시작 셀에서 한 번
PROB_NO = 1              # 문제마다 이 줄만 수정

SUBMIT_CSV = f'{PHONE}_{PROB_NO}.csv'
SUBMIT_MODEL = f'{PHONE}_{PROB_NO}.pkl'
```

손으로 매번 파일명을 치면 오타가 납니다. 변수 하나만 바꾸면 전부 따라오게 만드세요.
**세션당 한 번 정하는 것(GPU·PHONE)과 문제마다 바꾸는 것(PROB_NO)을 분리해 두는 것**이 핵심입니다.

### ⑤ 커널은 하나다 — 순서와 변수 이름이 걸린다

여러 문제를 **주피터 커널 하나에서** 풉니다. 여기서 두 가지가 따라옵니다.

**순서** — GPU를 많이 쓰는 문제부터 시작하세요.

```
1순위  이미지 (전이학습)    학습 10~30분
2순위  텍스트 BERT          학습 20~40분
3순위  텍스트 TF-IDF        몇 분
4순위  정형 (Tabular)       몇 분
```

학습이 도는 동안 손이 빕니다. 이미지 `fit()`을 먼저 걸어 두면 그 30분에 정형 문제 코드를 짤 수 있습니다.
반대로 하면 정형을 다 푼 뒤에야 학습이 시작되고, 그 30분은 화면만 보게 됩니다.

셀은 순서대로 실행되므로 학습 중에 다른 셀을 *실행*할 수는 없습니다.
할 수 있는 것은 *작성*이고, 작성해 둔 셀은 학습이 끝나는 즉시 이어서 돌아갑니다.

**변수 이름** — 전역 변수는 커널 전체가 공유합니다.
2번 문제의 `X_train`이 1번 문제의 `X_train`을 덮어쓰고, 1번으로 돌아가 셀 하나를 다시 돌리면
**에러 없이 틀린 결과**가 나옵니다. 그래서 이 과정의 템플릿은 모든 변수에 `p1_` 접두사를 붙였습니다.

```python
p1_PROB_NO = 1
p1_X_train, p1_X_val = ...      # 2번 문제는 Ctrl+H 로 p1_ → p2_ 일괄 치환
```

자세한 절차는 [04. 시험 당일](04-exam-day.md)의 "문제 순서"와 "변수 이름" 절에 있습니다.

> **연습은 Colab T4에서 하세요.** 시험 환경이 이와 비슷합니다.
> 다른 환경에 익숙해져 있으면 런타임 설정·파일 업로드·단축키에서 시간을 씁니다.
> 이 과정의 노트북과 템플릿은 **Colab T4에서 실행하는 것을 전제로** 작성했습니다.

## 3. 시간을 어디에 쓸 것인가

이 60분 과정은 Tabular에 17분, Text 13분, Image 12분을 배정합니다. 균등 배분이 아닌 이유:

- **Tabular가 전처리 판단이 가장 많다.** 결측치·이상치·인코딩·스케일링·불균형 — 사람이 결정할 지점이 5개 이상입니다.
- **Text와 Image는 전처리가 거의 정해져 있다.** 텍스트는 정제 + 벡터화, 이미지는 리사이즈 + 증강으로 끝납니다. 대신 모델 쪽(BERT, 전이학습)에 정형화된 레시피가 있고, 그 레시피만 외우면 됩니다.

그래서 Tabular는 "판단하는 법"을, Text·Image는 "레시피"를 다룹니다.

## 4. 세 도메인을 관통하는 뼈대

```
 1. 로드        df_train / df_test 를 읽는다
 2. EDA        결측·타입·분포·타겟 상관을 확인한다  ← 여기서 전처리 계획이 결정된다
 3. 전처리      train 에서 fit, test 는 transform  ← 시험에서 가장 많이 틀리는 곳
 4. 분할        train → X_train / X_val  (test 는 절대 건드리지 않는다)
 5. 모델 비교    후보 3~5개를 같은 조건으로 돌려 1위를 고른다
 6. 튜닝        1위 모델만 GridSearchCV
 7. 평가        Accuracy / F1 (분류), RMSE / R² (회귀)
 8. 제출        X_test 예측 → submission.csv
```

세 도메인에서 **3번과 5번만 달라집니다.**

| 단계 | Tabular | Text | Image |
|---|---|---|---|
| 3. 전처리 | 결측/인코딩/스케일링 | 정제 → TF-IDF 또는 토크나이저 | 리사이즈 → 정규화 → 증강 |
| 5. 모델 | RF / XGB / LGBM | LinearSVC / LogisticRegression, BERT | MobileNetV2 전이학습 |

나머지 1·2·4·6·7·8번은 코드가 거의 그대로 재사용됩니다.
`templates/` 안의 도메인 템플릿 네 개가 서로 닮아 보인다면, 그건 실수가 아니라 의도입니다.

## 5. 세 가지 습관

이 과정에서 반복해서 강조할 세 가지입니다. 나머지를 다 잊어도 이건 남기세요.

### ① 시드를 고정한다

```python
RANDOM_SEED = 42
np.random.seed(RANDOM_SEED)
tf.random.set_seed(RANDOM_SEED)   # 딥러닝을 쓸 때
```

돌릴 때마다 점수가 달라지면 "방금 바꾼 게 효과가 있었는지" 판단할 수 없습니다.
튜닝의 전제 조건이 재현성입니다.

### ② train에서 fit, test는 transform

```python
scaler = StandardScaler()
X_scaled      = scaler.fit_transform(X)        # train: fit + transform
X_test_scaled = scaler.transform(X_test)       # test: transform 만
```

`X_test`에 `fit_transform`을 쓰면 test의 평균·분산이 모델에 새어 들어갑니다(데이터 누수).
검증 점수는 오히려 올라가기 때문에 **틀렸다는 사실조차 눈치채기 어렵습니다.** 그래서 위험합니다.

같은 원칙이 결측치 대치(`SimpleImputer`), 인코딩(`LabelEncoder`), TF-IDF(`TfidfVectorizer`)에 전부 적용됩니다.

### ③ 이진/다중을 코드로 분기하지 않는다

```python
NUM_CLASSES = df_train[TARGET].nunique()
```

클래스 수를 변수로 뽑아 두면, 이진분류든 7개 다중분류든 **같은 코드가 돕니다.**
딥러닝 쪽에서는 이 원칙이 특히 강력합니다. 출력층을 `sigmoid` + `binary_crossentropy`가 아니라
항상 `softmax` + `categorical_crossentropy`로 통일하면, 클래스 수만 바꿔 끼우면 끝입니다.

시험장에서 데이터를 열어 보고 "아 3개짜리네, 코드 고쳐야겠다" 하는 순간 5분이 날아갑니다.

## 6. 성능 판단 기준

모델을 돌린 뒤 "이 정도면 된 건가?"를 매번 고민하지 않도록, 기준선을 미리 정해 둡니다.

| Accuracy | 판정 | 행동 |
|---|---|---|
| 0.95 이상 | 매우 우수 | 제출하고 다음 문제로 |
| 0.90 ~ 0.95 | 우수 | 시간 남으면 튜닝 |
| 0.85 ~ 0.90 | 양호 | 피처 엔지니어링 검토 |
| 0.80 ~ 0.85 | 보통 | 전처리 재점검 |
| 0.80 미만 | 미흡 | 데이터/타겟 해석이 틀렸을 가능성 |

**Accuracy와 F1(macro)의 차이도 함께 보세요.**
둘이 비슷하면 클래스 균형이 맞는 것이고, `Accuracy >> F1`이면 소수 클래스를 못 맞히고 있다는 신호입니다
(→ `class_weight='balanced'` 또는 SMOTE 검토).

회귀에서는 R²를 같은 방식으로 씁니다: 0.9 이상 매우 우수, 0.8 이상 우수, 0.6 미만이면 재검토.
