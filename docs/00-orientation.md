## 1. 이 시험의 성격

주피터 노트북 환경에서 데이터를 받아 **모델을 만들고 예측 결과를 제출**합니다.
총 **180분**, 정형(Tabular) · 텍스트(Text) · 이미지(Image) 중 하나 또는 둘이 출제됩니다.

> "주어진 `train.csv`로 모델을 학습시키고, `test.csv`에 대한 예측 결과를 저장하시오."

실점은 대부분 모델 성능이 아니라 절차에서 납니다.

- 전처리를 test에도 똑같이 적용했는가
- 스케일러를 test로 `fit` 하지 않았는가
- 제출 파일의 행 수와 컬럼명이 요구사항과 맞는가

정확도 0.93을 0.95로 올리는 일보다 **끝까지 도는 코드를 시간 안에 완성하는 일**이 점수에 직결됩니다.

## 2. 시험 환경 여섯 가지

실력과 무관하게 점수를 잃는 지점입니다.

### ① 문제와 함께 분석 자료가 주어진다

컬럼 설명, 데이터 정의, 요구사항이 문서로 제공됩니다. 데이터를 뒤져서 알아내는 시험이 아닙니다.
코드를 치기 전에 읽고 이것부터 확정하세요.

- 타겟 컬럼
- 각 컬럼의 의미 (→ **누수 컬럼이 여기서 드러납니다**)
- 제출 파일 형식과 요구 지표

[01. Tabular](01-tabular.md)의 "컬럼 요약표"는 분석 자료를 **교차 검증하는 도구**입니다.
자료에 "결과값을 사후 기록한 컬럼"이라 적혀 있으면 상관계수를 볼 것도 없이 제거합니다.

### ② GPU는 자동으로 붙지 않는다

시험 환경의 GPU는 Colab 무료 T4와 비슷한 수준이지만, **연결 코드를 직접 실행해야 합니다.**

```python
# 시험 시작 후 첫 번째 셀
!nvidia-smi

import tensorflow as tf
gpus = tf.config.list_physical_devices('GPU')
print(f"GPU: {gpus}")
assert gpus, "GPU 미연결! 런타임 설정을 확인하세요"
```

빠뜨리면 코드가 **에러 없이 CPU로 떨어집니다.** 전이학습과 BERT가 수십 배 느려지므로
`assert`로 멈춰 세웁니다.

세션이 유지되는 동안에는 한 번이면 됩니다. 그래서 GPU 확인은
[templates/00_session_start.py](../templates/00_session_start.py) 한 곳에만 두었습니다.

**단, 세션이 튕기면 다시 연결해야 합니다.** 런타임이 재시작되면 GPU가 떨어지고,
재연결 시 CPU로 붙는 경우가 있습니다.

### ③ 중간저장은 코드만 지킨다

시험 환경에는 **중간저장** 기능이 있습니다. 지켜 주는 범위가 정해져 있습니다.

| | 중간저장 | 세션이 튕기면 |
|---|---|---|
| 작성한 **코드** | 저장 지점까지 보존 | 저장 지점 이후만 소실 |
| 커널 **변수** (전처리 결과, 모델) | **보존 안 됨** | **전부 소실** |
| **GPU 연결** | 무관 | **끊김 — 다시 연결** |

**코드는 중간저장으로, 학습 결과는 파일로.** 30분 걸린 학습은 중간저장이 살려 주지 않습니다.

- 단계가 끝날 때마다 중간저장
- 긴 학습을 시작하기 **직전에** 반드시
- 학습이 끝나면 **즉시 모델을 파일로**

시험장에서 새로 생기는 습관이 아닙니다. 연습할 때부터 저장하세요.

### ④ 제출 파일명은 휴대폰 번호 + 문제 번호

```
01012345678_1.pkl     # 1번 문제의 모델
01012345678_1.csv     # 1번 문제의 예측 결과
```

하이픈 없이 붙여 씁니다. 이름이 틀리면 채점이 안 될 수 있으므로 직접 타이핑하지 말고
변수로 한 번만 정합니다.

```python
PHONE = '01012345678'    # 세션 시작 셀에서 한 번
PROB_NO = 1              # 문제마다 이 줄만 수정

SUBMIT_CSV = f'{PHONE}_{PROB_NO}.csv'
SUBMIT_MODEL = f'{PHONE}_{PROB_NO}.pkl'
```

**세션 단위로 정하는 것(GPU·PHONE)과 문제마다 바꾸는 것(PROB_NO)의 분리**가 핵심입니다.

### ⑤ 예측값은 label로 복원한다

파일명만이 아니라 **CSV 내용도 채점 대상**입니다.
예측 컬럼명과 값은 문제가 요구한 label 그대로 — 인코딩된 숫자(0/1/2)로 내면 **0점**입니다.

```python
pred = best_model.predict(X_test)              # [0, 2, 1, ...]
pred = target_encoder.inverse_transform(pred)  # ['cat', 'dog', ...]
```

이미지는 `class_names[i]`, 텍스트는 `label_map`이 같은 역할을 합니다.

템플릿 마지막 셀이 이걸 자동으로 점검합니다 — 세션 시작 셀에 정의된 `check_submission()`이
행 수·컬럼·결측·label을 확인하고, 텍스트·이미지는 **눈 검증**(원문·그림과 예측 대조)이 뒤따릅니다.

### ⑥ 커널은 하나다

여러 문제를 **주피터 커널 하나에서** 풉니다. 두 가지가 따라옵니다.

**순서** — GPU를 많이 쓰는 문제부터.

```
1순위  이미지 (전이학습)    학습 10~30분
2순위  텍스트 BERT          학습 20~40분
3순위  텍스트 TF-IDF        몇 분
4순위  정형 (Tabular)       몇 분
```

이미지 `fit()`을 먼저 걸어 두면 그 30분에 정형 문제 코드를 작성할 수 있습니다.
반대 순서면 정형을 다 푼 뒤에야 학습이 시작됩니다.
셀은 순서대로 실행되므로 학습 중에 다른 셀을 *실행*할 수는 없고 *작성*만 가능합니다.
작성해 둔 셀은 학습이 끝나는 즉시 이어서 돌아갑니다.

**변수 이름** — 전역 변수는 커널 전체가 공유합니다.
2번 문제의 `X_train`이 1번 것을 덮어쓰고, 1번으로 돌아가 셀 하나를 다시 돌리면
**에러 없이 틀린 결과**가 나옵니다. 그래서 템플릿마다 시험 순서대로 접두사가 미리 붙어 있습니다.

```python
p1_X_train = ...   # 1번 Tabular
p2_X_train = ...   # 2번 Text
p3_model   = ...   # 3번 Image   — 순서가 다르게 나올 때만 Ctrl+H 로 치환
```

절차는 [04. 시험 당일](04-exam-day.md)의 "문제 순서"와 "변수 이름" 절에 있습니다.

> **연습은 Colab T4에서.** 시험 환경이 이와 비슷합니다.
> 이 과정의 노트북과 템플릿은 T4 실행을 전제로 작성했습니다.

## 3. 시간을 어디에 쓸 것인가

45분 강의를 Tabular 13분, Text 10분, Image 9분으로 배분합니다. 균등 배분이 아닌 이유:

- **Tabular는 사람이 결정할 지점이 많다.** 결측치·이상치·인코딩·스케일링·불균형 — 다섯 개 이상.
- **Text와 Image는 전처리가 거의 정해져 있다.** 대신 모델 쪽(BERT, 전이학습)에 외울 레시피가 있습니다.

Tabular는 "판단하는 법", Text·Image는 "레시피"를 다룹니다.

## 4. 세 도메인을 관통하는 뼈대

```
 1. 로드        df_train / df_test 를 읽는다
 2. EDA        결측·타입·분포·타겟 상관을 확인한다  ← 여기서 전처리 계획이 결정된다
 3. 전처리      train 에서 fit, test 는 transform  ← 가장 많이 틀리는 곳
 4. 분할        train → X_train / X_val  (test 는 절대 건드리지 않는다)
 5. 모델 비교    후보 3~5개를 같은 조건으로 돌려 1위를 고른다
 6. 튜닝        1위 모델만 GridSearchCV
 7. 평가        Accuracy / F1 (분류), RMSE / R² (회귀)
 8. 제출        X_test 예측 → 제출 파일
```

세 도메인에서 **3번과 5번만 달라집니다.**

| 단계 | Tabular | Text | Image |
|---|---|---|---|
| 3. 전처리 | 결측/인코딩/스케일링 | 정제 → TF-IDF 또는 토크나이저 | 리사이즈 → 정규화 → 증강 |
| 5. 모델 | RF / XGB / LGBM | LinearSVC / LogisticRegression, BERT | MobileNetV2 전이학습 |

나머지 여섯 단계는 코드가 거의 그대로 재사용됩니다.
도메인 템플릿 네 개가 닮아 보이는 것은 의도한 결과입니다.

준비물도 이 네 벌로 끝납니다 — **Tabular 분류·회귀, Text 다중분류, Image 다중분류.**
이진분류 템플릿은 없습니다. 클래스 2개인 다중분류가 곧 이진분류이므로,
Text와 Image는 다중 한 벌만 준비하면 이진 문제가 나와도 그대로 돕니다.

시험 문제 순서는 **1번 Tabular · 2번 Text · 3번 Image**로 고정입니다.
템플릿 파일명(01·02·03)과 변수 접두사(`p1_`·`p2_`·`p3_`), `PROB_NO`가 이 순서에 미리 맞춰져 있습니다.

## 5. 세 가지 습관

나머지를 다 잊어도 이건 남기세요.

### ① 시드를 고정한다

```python
RANDOM_SEED = 42
np.random.seed(RANDOM_SEED)
tf.random.set_seed(RANDOM_SEED)   # 딥러닝을 쓸 때
```

돌릴 때마다 점수가 달라지면 방금 바꾼 것의 효과를 판단할 수 없습니다. 재현성이 튜닝의 전제입니다.

### ② train에서 fit, test는 transform

```python
scaler = StandardScaler()
X_scaled      = scaler.fit_transform(X)        # train: fit + transform
X_test_scaled = scaler.transform(X_test)       # test: transform 만
```

`X_test`에 `fit_transform`을 쓰면 test의 평균·분산이 모델에 새어 들어갑니다(데이터 누수).
검증 점수는 **오히려 올라가므로** 틀렸다는 사실을 눈치채기 어렵습니다.

같은 원칙이 `SimpleImputer`, `LabelEncoder`, `TfidfVectorizer`에 전부 적용됩니다.

### ③ 이진/다중을 코드로 분기하지 않는다

```python
NUM_CLASSES = df_train[TARGET].nunique()
```

클래스 수를 변수로 뽑아 두면 이진분류든 7개 다중분류든 같은 코드가 돕니다.
딥러닝에서는 출력층을 `sigmoid` + `binary_crossentropy` 대신 항상
`softmax` + `categorical_crossentropy`로 통일하면 클래스 수만 바꿔 끼우면 됩니다.

## 6. 성능 판단 기준

"이 정도면 된 건가"를 매번 고민하지 않도록 기준선을 미리 정합니다.

| Accuracy | 판정 | 행동 |
|---|---|---|
| 0.95 이상 | 매우 우수 | 제출하고 다음 문제로 |
| 0.90 ~ 0.95 | 우수 | 시간 남으면 튜닝 |
| 0.85 ~ 0.90 | 양호 | 피처 엔지니어링 검토 |
| 0.80 ~ 0.85 | 보통 | 전처리 재점검 |
| 0.80 미만 | 미흡 | 데이터/타겟 해석이 틀렸을 가능성 |

Accuracy와 F1(macro)를 함께 봅니다. 둘이 비슷하면 클래스 균형이 맞는 것이고,
`Accuracy >> F1`이면 소수 클래스를 못 맞히고 있다는 신호입니다
(→ `class_weight='balanced'` 또는 SMOTE 검토).

회귀는 R²를 같은 방식으로 씁니다: 0.9 이상 매우 우수, 0.8 이상 우수, 0.6 미만 재검토.
